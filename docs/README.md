# docs 索引

这里放的是**随代码走的工作手册**：换机器、换人、隔三个月回来接手，靠这两份文档把上下文接上。
与 README.md 的分工是：README 讲「这个产品能做什么、怎么装」，这里讲「这个项目是怎么做到今天的、
下一步该做什么、哪些坑已经踩过、怎么做」。

## 入库前过的脱敏清单（2026-11-05 建立，2026-11-10 复跑）

两本手册逐条过下面几项，结论写在后面：

1. **真实公网 IP / 域名 / 在线赛题 URL** —— 全文没有 IPv4 字面量，网络拓扑一律写
   `<内网IP>`、RFC1918 段（`10.99.0.0/24`、`10.10.0.0/24`、`172.17.0.0/16`）或占位主机名。出现的域名只有
   `ghcr.io`（本项目镜像仓库）、`goproxy.cn`、`registry.npmmirror.com`、`ghcr.nju.edu.cn` 这类公共
   基础设施，以及公开上游仓库的 GitHub 链接。**通过**
2. **任何口令、token、私钥、sidecar 管理员口令** —— 只有读取方式（`docker exec … printenv`、
   `<PW>`、`${PW}`）和「不落盘、不回显」的纪律，没有值。**通过**
3. **内部阶段代号 P0/P1** —— 已改成能力名。全文剩下的 `P0/P1/P2` 只出现在一处：
   开发手册 §11 里「不要写内部代号」这条规则本身。**通过**
4. **内部编号（R1–R11、批次号、历史任务号 `#88`）** —— 允许留在 `docs/` 这两本内部台账里，
   但**不得出现在公开文件**（`CHANGELOG.md` / `README.md` / `DEPLOY.md` /
   `.github/release-notes/*.md`）；引用代码时给路径，别给行号。**通过**
5. **靶机拓扑细节** —— 保留，但一律用文档网段与发行版名，不指向任何可被外部访问的地址。**通过**
6. **大二进制** —— 不提交（封面 PNG 已排除），仓库不依赖 git-lfs。**通过**

## 维护约定

- **只有两本**：新的长期内容并进对应一本（做法→开发手册，账目→进度手册），不再另起专题文档；
  临时记录放本机，收口时并入。
- **欠账只登记一处**：进度手册 §5。别在 CHANGELOG、提交信息或别处维护待办清单。
- 文档里写事实与原因，不写只有当时才懂的代号；引用代码时给路径，行号会漂。
- 每次大版本发版前，把上面 6 条清单重跑一遍——文档会随时间积累出当时看起来无害、
  后来变成泄露面的内容。
