   容器重建抹掉 `/app/data/evidence` 后该 0 字节 blob 不存在，`copySnapshots` 一律报错拖垮导出。
   修复：对「长度 0 + 空正文哈希」直接还原 0 字节文件（内容可由哈希无损校验），非空正文缺失
   仍报错以保证证据完整性。夹具：`TestCopySnapshotsRecoversMissingEmptyBody`。

### 5.4 设计：LLM 活性监督与中断恢复（R21，实现时照此做）

前提共识：**「在工作」的定义是有进展，不是进程活着**。今天这个任务跑了 16 小时、71 轮、
96.4M 输入 token，`goal met` 仍是 0——只靠「进程在」这套判据完全看不出异常。

**① 三层判据**

| 层 | 信号 | 判定阈值（建议默认，实现时做成可配） |
| :-- | :-- | :-- |
| L1 传输 | 每次 LLM 调用的**首个流事件**时刻 | 超 `T1=45s` 无事件判 `stalled`，主动 cancel 这一发 |
| L2 轮次 | 每轮 `status / error_class / attempts / trigger_src` | 轮要么产出、要么显式失败计数，禁止无声结束 |
| L3 任务 | goal met 增量、intent 状态迁移、新资产/新漏洞、token 消耗 | 连续 `N=5` 轮零进展 → `stalled_task`，停下来问人 |

现有 `llmCallTimeout` 默认 15 分钟是给 thinking 模型留的宽口子，**不能用它判卡住**：
一轮卡满 15 分钟期间 `inflight` 一直被占着。L1 就是新增的那把刀。

**② 留痕不依赖正文录制开关**（R15 的正解）：新增 `llm_round(task_id, round_no, trigger_src,
status, error_class, attempts, profile_id, tokens_in, tokens_out, started_at, last_event_at)`，
幂等迁移；`llm_profile_health` **无论池是否启用都记失败**——启用只决定「要不要切换」，
不决定「要不要记账」。

**③ 五类错误与处置**（分类才有不同动作，否则只能统一重试）

| class | 例子 | 处置 |
| :-- | :-- | :-- |
| `transport_reset` | `stream ID 633; INTERNAL_ERROR`、connection reset | 同 profile 重试 1 次 → 退避 5/15/45s → 再失败切链 |
| `stalled` | 建连成功但 `T1` 内无事件 | cancel 后按 `transport_reset` 处理，并计入该端点劣化率 |
| `rate_limited` | 429 / 队列满 | 按 `Retry-After` 退避，**不计入熔断**（限流不是宕机） |
| `account_invalid` | 401 / 402 / 403（今天两条 profile 就是这样） | **不重试**：立刻判该配置不可用、切链或停任务，提示「欠费/未订阅」 |
| `empty_response` | 完成但无 content block | 走已有空响应重试语义 |

**④ 中断后的继续机制——三条不丢**

1. **触发不丢**：`drainTriggers()` 改成失败回灌或 peek-commit，杜绝「worker 完成了但 planner
   从没看到」而永久停滞；
2. **钱不重复烧**：重试轮不得重复创建同源意图（复用 `CompareAndSetIntentState` 的 CAS），
   且本轮已产出的意图要先落库再算成功；
3. **状态不乱**：三条既有不变量必须保持——终态任务不重规划、pause 可取消、goalless 不跑 planner。
   链耗尽时落新状态 **`llm_unavailable`**（不再用 `created`/`running` 二义表达），并**停掉 heartbeat 空转**。

**⑤ 预算与收敛闸门**（与 R19 一并解决）：任务级 `max_rounds`、`max_input_tokens`、wall clock
（`timeout_seconds` 已存在，等 R12 重建后生效）+ 进展停滞自动判定；到限就收尾并输出
「哪些 goal 没完成、还差什么」，不许无限续命。

**⑥ 看得见**：任务详情显示「当前轮：流式中 / 重试第 k 次（原因）/ 已切链 / 等 429 退避」；
新增 `GET /api/tasks/{id}/llm-health`，形态抄 `guard_denials` 的按成因分布；废轮率超阈值
（建议 30%）直接告警「该中转端不可用」——今天实测 **45%**。

**⑦ 判据反向验证**（I4 老规矩）：夹具必须人造 `stalled` / `transport_reset` / `account_invalid`
三种故障，断言「被检出 → 按类处置 → 留痕进 `llm_round` → 不重复烧钱」；**人造坏轮必须能让流水线红**，
否则这层门是摆设。

**⑧ 落地位置与风险**：`server/engine.go`（plannerLoop 与 triggers）、`llmpool/`（分类与记账）、
`llmrec/`（事件时间戳）、`db/`（新表迁移）、`server/llmpool.go` 与前端任务详情。
改的是执行循环，**必须等实机任务到终态后再动**，重建会打断它。归 1.6.3，与 R15/R19 同批。
