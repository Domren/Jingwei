## 二、逐项验收结论

### 平台侧 P1–P8

- **P1 操作端反溯源 — 通过**。`GET /api/audit/export?format=md` 返回：操作者 `Jingwei`、授权书引用字段、操作会话隔离 `true`、任务 #1 操作流水（工具/动作/命令已脱敏）。设置项 `operation_proxy_chain`/`operator_session_isolation`/`audit_authorization_ref` 均存在。
- **P2 多出口代理池 — 通过（绑定与留痕）**。`egress_endpoints` 插入两条出口（egress-A/B），`task_egress_bindings` 绑定任务1→A、任务2→B；`task_id` 有 UNIQUE 约束防串用。字段 `healthy`/`failures`/`last_error` 支撑健康探测与失败轮换（行为由 `egress_pool_test.go` 夹具覆盖，未搭真实坏出口）。
- **P3 站群资产聚类 — 通过**。用真实靶机 10 域名骨架数据调 `ClusterAssets`：返回 2 族、每族 5 成员；`ClusterKeyFor` 按 cert>page>favicon>dedupe 优先级取键，原始条目保留。
- **P4 请求节奏自适应 — 通过**。`AdaptivePacer` 三形态识别由 `pacing_test.go` 夹具覆盖；靶机 `/rate/` 实测连发 6 次 `200 200 200 503 503 503`，限速特征可被识别。一个目标降速不拖垮其他任务由夹具验证。
- **P5 蜜罐行为识别 — 通过**。靶机 `/honey/?cmd=whoami` 任意 payload 均 success（过度完美），`DetectBehavior` 判据由夹具覆盖；强制二次验证只提示不阻断 normal。
- **P6 api-recon 自动化 — 通过**。靶机混淆 JS 提取出 `/api/v2/users|orders|admin/roles|config`；`js_denoise_extract.py` 夹具通过，与目录枚举去重。
- **P7 批量任务工作流 — 通过**。`BuildBatchSpawnPlan(10 目标)` → 10 子任务；重复目标去重 `a,a,b,空,b → 2`。跨任务 dedupe_key 不误合由 `batch_aggregate_test.go` 覆盖。
- **P8 被动线索入口 — 通过（默认关）**。`GET /api/settings` 返回 `passive_leads_enabled=false`；接口固定不可填、跨主机重定向拒绝由 `egress_passive_test.go` 夹具覆盖。

### RCE P9–P11

- **P9 RCE 验证阶梯 — 通过（核心验收项全中）**。深任务 API：
  - `rce_verify` 第1级（回连证明）→ 引擎日志 `[deep] RCE 阶梯已授权第 1 级（回连证明）`，status=done；
  - 跳级（achieved=0 直接请求 level=3 读文件）→ 引擎日志 `[deep] RCE 阶梯复核未通过：跳级请求：当前已授权第 0 级，却直接请求第 3 级（读文件）；必须人工审批`，status=failed。
  - 四级独立开关参数 `rce_callback/harmless/read/write` 已写入任务 params，代码闸门入队前+执行侧双复核。
- **P10 执行结果置信度 — 通过（落库+判定）**。插入两条 finding：`P10-observed-真回连`（confidence=observed, status=confirmed）、`P10-inferred-WAF改写`（confidence=inferred, status=pending），DB 值域正确。`NormalizeFindingConfidence` 与报告层只引用 observed 由 `confidence_test.go` 覆盖。（注：`/api/report` 读 exploration_nodes 表而非 findings 表，报告层过滤走 `BuildFindingReport` 路径，由单测覆盖。）
- **P11 java-chains 无 sidecar — 通过**。`GET /api/deep/java-chains/status` → `configured=false, error=JAVA_CHAINS_MCP_TOKEN 未配置`。`ProbeJavaChainDependency("fastjson2", 含 com.alibaba.fastjson2 的证据)` → `status=dependency_present, signal=com.alibaba.fastjson2, note=依赖存在（线索），但无 sidecar，链未验证`；空 family → `status=no_java_chain, note=目标无该链（不是「待复核」）`。

### 权限维持 P12–P14

- **P12 环境适配探测 — 通过**。真实靶机经 webshell 执行探测命令，拿到 `JW_PROBE_CONTAINER=no / CRONTAB=yes / HOME=no / SYSTEMD=yes / EDR=none`；webshell 注入时自动带 `php_env`（`exec_available=true, file_available=true`）。5 类环境判定与「不适用不生成命令」由 `intranet_persist_env_test.go` 夹具覆盖。
- **P13 TTL 自动回收 — 通过**。插入过期产物（expires_at 为 1 小时前）→ `ListExpiredIntranetArtifacts(now)` 识别命中 → 无可用会话时 `MarkIntranetArtifactTTLFailedManual` → `status=revoked, ttl_revoke_status=failed_manual`；人工队列单列查询返回 1 条，不混入「平台已验证清除」。默认关（settings 无 ttl 记录）。
- **P14 痕迹矩阵动态更新 — 通过**。`TraceMatrixMarkdown` 输入含 `Observed`/`ProfileDiff` → markdown 含「crontab」与「静态档案未描述」标注；`Unknown=["无可用会话"]` → 单列展示，不与「采集了但无差异」混同。

### 木马隐蔽 P15–P18

- **P15 载荷族归并 — 通过**。靶机真实落地 3 个 webshell。注入时 family_id 按模板+密钥版本生成：shell#2/#3 同为 `fam_65172ffa…`（kv1）。族批量轮换 `POST /api/deep/webshell-families/{fid}/rotate` → `succeeded=2, total=2`；轮换后 shell2/3 的 `whoami`/`id -u` 均 exit_code=0；三壳随 kv2 重组为同一族。单壳指纹 `payload_sha256` 与 family_id 均可查。
- **P16 密钥轮换原子性 — 通过**。`POST /api/deep/webshells/1/rotate` → key_version 1→2；轮换前后各执行一次 `whoami`，均 `exit_code=0, marker_ok=true`，输出 `www-data`。双密钥过渡期由 `shell_secret_rotation_test.go` / `shell_crypto_rotation_test.go` 夹具覆盖（旧/新密文双向可解、窗口结束收口）。
- **P17 心跳隐蔽性 — 通过**。webshell 落地后空闲 65 秒，靶机 nginx 访问日志新增请求 **0 条**（无自发心跳）；有操作时正常通信（exec 33–66ms）。时间戳+nonce 防重放由夹具覆盖。
- **P18 部署前冲突检测 — 通过**。向已存在的 `/uploads/legit.php` 注入 → 落地探测标记 `JW_FILE_EXISTS`（HTTP 200），任务 status=blocked，错误「未覆盖，已转人工核对授权方资产」，生成冲突记录 `webshell_deploy_conflicts` id=1。对照：向空路径注入时标记 `JW_FILE_NEW`（HTTP 404）才继续。

### Shell 管理 P19–P20

- **P19 多会话标签化 + 批量只读 — 通过**。`POST /api/deep/webshells/batch-exec` 对 3 个会话批量 `whoami` → 全部 `www-data`、exit_code=0、marker_ok=true；批量 `rm -rf /tmp/test` → guard 拒绝「命令『rm』不在只读白名单内，批量执行已拒绝（写操作请逐条审批）」。会话标签字段 `Labels []string`（JSONB+GIN）已在 DB。
- **P20 会话管理三项 — 通过（续传项实机）**。大文件续传：`/api/deep/webshells/1/file` 分片读取靶机 `big.bin`（3145728 字节，256KiB×12 片），重组 SHA256 `7e8d2ff9343785989ce6ca81102bf6319c51d5002dd5a1664b85070a375730bb` 与靶机 `sha256sum` 完全一致，字节级一致。失效原因四类分类与审计导出由 `intranet_health_failure_test.go` / `intranet_events_export_test.go` 夹具覆盖。

## 三、验收过程发现并修复的问题

1. **schema.sql 迁移顺序错误（真 bug）**：P19 的 `intranet_sessions.labels` 列 `ADD COLUMN IF NOT EXISTS` 写在 GIN 索引之后，旧库启动失败（`column labels does not exist`）。已修复并提交 `7f3816f`。
2. **镜像不含新代码**：Dockerfile 只 `COPY dist/${arch}/jingwei` 不编译，容器一直跑旧二进制（`rce_verify` 不存在且段错误）。正确流程：先本地 `go build -tags embedui -o dist/amd64/jingwei ./cmd/jingwei`，再 docker build。
3. **JINGWEI_PG_DSN 环境变量泄漏**：用宿主 DSN（127.0.0.1:55432）跑 Go 工具后未 unset，compose 注入容器导致容器内连不上 DB。compose 前必须 `unset JINGWEI_PG_DSN`。
4. **御界中转站 chat 端点间歇性挂起**：models 接口正常但 chat 40–50s 超时，精卫报 `stalled`。为完成验收临时任务级切 `8888ok-备用`，完成后恢复御界为全局激活。稳定性属中转站侧问题。
