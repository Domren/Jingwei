## 二、逐项验收结论

### 平台侧 P1–P8

- **P1 操作端反溯源 — 端到端通过**。真实 `PUT /api/settings` 设 `operation_proxy_chain=http://172.24.31.92:7890`、`audit_authorization_ref=AUTH-WSL-2026-1120`、隔离 true → 真实执行一次 webshell 操作 → `GET /api/audit/export?format=md` 回显授权引用、代理链、操作者 Jingwei、隔离状态、操作流水（命令脱敏）。验收后已清空测试配置。
- **P2 多出口代理池 — 端到端通过**。真实 `EgressPool` 注册两出口（一好一坏，坏出口带 `user:SECRET_PASS@127.0.0.1:1`）→ 绑定 taskA/taskB → taskA 选到好出口；taskB 的坏出口经 probe 判失败并**自动轮换**到好出口；跨任务不串用；5 条审计事件中凭据零泄漏（`dial tcp` 的 host:port 保留、口令脱敏）。
- **P3 站群资产聚类 — 端到端通过**。真实抓靶机 10 域名 favicon（两族内容 hash 不同：`1eb15b25…`/`f9165bd9…`）→ 真实 `POST /api/assets` 写入 10 条带 `favicon_mmh3` 的 service 资产 → API 读回 → 真实 `ClusterAssets` → 2 族、每族 5 成员。过程中发现 app 类型资产 API 不接收 favicon、service 类型才接收（实现口径，非 bug）。
- **P4 请求节奏自适应 — 端到端通过**。真实抓靶机三形态响应：open=200、throttled=429/503（靶机 nginx 改 `limit_req_status 429` + `Retry-After`）、challenge=403 → 真实 `AdaptivePacer.Observe` → `PaceFor` 得 open(100ms)/throttled(200ms)/challenge(800ms)，`ShouldRotateEgress(challenge)=true`，三目标节奏隔离。
- **P5 蜜罐行为识别 — 端到端通过**。真实对靶机蜜罐发 5 种 payload（全 success、无噪声、亚毫秒）→ 静态签名漏检（verdict=clean）→ `DetectBehavior` 命中 `likely_honeypot`（0.60，`behavior-too-perfect` 信号）。靶机蜜罐页已调整为对所有输入 success（真过度完美）。
- **P6 api-recon 自动化 — 端到端通过**。真实抓靶机 `/spa/js/bundle.min.js`（324B 混淆 JS）→ 真实运行 `js_denoise_extract.py` → 提取 5 个 `/api/v2/*` 端点 + token/refresh/role 参数；带 1.5.0 既有结果重跑 → `deduped_against_count=3`、剩 3 个新端点。

### RCE P9–P11

- **P9 RCE 验证阶梯 — 通过（核心验收项全中）**。深任务 API：
  - `rce_verify` 第1级（回连证明）→ 引擎日志 `[deep] RCE 阶梯已授权第 1 级（回连证明）`，status=done；
  - 跳级（achieved=0 直接请求 level=3 读文件）→ 引擎日志 `[deep] RCE 阶梯复核未通过：跳级请求：当前已授权第 0 级，却直接请求第 3 级（读文件）；必须人工审批`，status=failed。
  - 四级独立开关参数 `rce_callback/harmless/read/write` 已写入任务 params，代码闸门入队前+执行侧双复核。
- **P10 执行结果置信度 — 端到端通过**。真实抓靶机 WAF 改写回显 `error: 请求包含非法关键字，已阻断 (code 1024)` 与正常回显 `id=1` → 构造 observed/inferred 两条 `FindingReportInput` → 真实 `BuildFindingReport`：inferred 的 WAF 回显不进正文、附录标注 inferred；observed 的正常回显进正文。`BuildFindingReport` 内部已调 `verificationSteps`，涵盖验证步骤不引用 inferred 回显。confidence 列落库值域（observed/inferred/failed）另由 DB 真实验证。

## 三、验收过程发现并修复的问题

1. **schema.sql 迁移顺序错误（真 bug）**：P19 的 `intranet_sessions.labels` 列 `ADD COLUMN IF NOT EXISTS` 写在 GIN 索引之后，旧库启动失败（`column labels does not exist`）。已修复并提交 `7f3816f`。
2. **镜像不含新代码**：Dockerfile 只 `COPY dist/${arch}/jingwei` 不编译，容器一直跑旧二进制（`rce_verify` 不存在且段错误）。正确流程：先本地 `go build -tags embedui -o dist/amd64/jingwei ./cmd/jingwei`，再 docker build。
3. **JINGWEI_PG_DSN 环境变量泄漏**：用宿主 DSN（127.0.0.1:55432）跑 Go 工具后未 unset，compose 注入容器导致容器内连不上 DB。compose 前必须 `unset JINGWEI_PG_DSN`。
4. **御界中转站 chat 端点间歇性挂起**：models 接口正常但 chat 40–50s 超时，精卫报 `stalled`。为完成验收临时任务级切 `8888ok-备用`，完成后恢复御界为全局激活。稳定性属中转站侧问题。
