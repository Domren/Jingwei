## 3. 欠账执行计划（2026-11-10 规划，落点 **1.6.2 靶场补齐版**）

> 原则不变：条件不到位就不做，**不拿进程内桩或推断替代真机结论**；每批做完先补本表状态再谈发版。

### 批 A · 立即可做（无外部依赖，约半天）
- **R3 补钉夹具**：「PS 会话生成的上传/下载/撤销命令确为 PowerShell 语法、不含 cmd 守卫 marker」
  是纯函数逻辑，**现在就能测**——把命令构造从执行路径里抽成可测函数，按既有
  `TestPowerShellSSHTransportNeverSeesCmdScripts` 的靶机模式补正反两例（cmd 会话出 cmd 脚本、
  PS 会话出 PS 脚本）。
- **R6 的读表动作定死**：1.6.2 收口当天执行 `GET /api/intercept/guard/denials?hours=168×N`，
  按成因分布给出「加/不加短暂重试+明确降级提示」的结论与依据；**回到放行不是选项**。
  期间日常照常用实例跑任务攒真实样本。
- **R11**：与 1.6.2 收口一起做（统计脚本化更好，顺手评估）。

### 批 C · 低 JDK 三容器（本机 docker，约半天，可立即开始）
- **搭法**：`eclipse-temurin:8uXXX-jre` / `11-jre` / `17-jre` 各配一个 Tomcat（9），应用是
  **自写的反序列化测试 servlet**（POST 体 `readObject`，classpath 挂 commons-collections
  3.2.1/1 件套），只挂 `10.10.2.0/24` 网段与回调端口绑回环；java-chains sidecar 用本机已有
  镜像（`jingwei-java-chains-1` 那套）进同一网络。
- **验证点**：① 三台各跑 `kind=java_deser` 深度任务，`PlanJavaChain` 的四条路线在真 JDK 上
  给出可测差异（8：远程类加载可用；11：局部退化点；17：`trustSerialData` 拒 JNDI 远程类）；
  ② java-chains 拿一次 **`outcome=exec`**（回连退出码证据，不是「已投递」）——这一条同时了结
  E1；③ E3 A 段内存马在 Tomcat9/各 JDK 上真注入真移除。
- **诚实边界**：具体哪个 gadget 在哪个补丁版本失败，**如实登记，不为凑 exec 挑软柿子后只报好的**。

### 批 D · Samba AD 靶域（本机 docker，约半天，可立即开始）
- **搭法**：`docker run thegeeklab/samba`（AD DC 模式，REALM `JINGWEI.LOCAL`，端口
  53/88/389/445/464/636/3268 只绑回环或 lab 网段）+ 一个 join 的成员容器（或直接域内两个用户）：
  建 `sqlsvc` 服务账号挂 SPN、密码进弱口令字典；keytab 用容器内 kadmin 现场生成。
- **验证点**：① R5 的 SPN 采集 → TGS 抓取（真 hash，离线 crack 用弱口令字典出结果）；
  ② LDAP 简单 bind 的凭据域内可用性判定落六态；③ 信任边进拓扑——**单域没有跨域信任，
  trusts 解析就明确标「本环境无从验证」，不硬造边**；④ `credscan` 的 LDAP/LDAPS 在真 AD 上
  复跑 hit/deny（比现用的 openldap 更真）。
- **做完的标准**：F2 从「未验证」升级为「Samba AD 上验证通过，Microsoft AD DS 未验证」——
  两者实现差异（如 LDAP channel binding、SMB 签名策略）逐项列出，不含糊。

### 批 B · Windows 靶机（**需要负责人授权动宿主**，动手前先确认）
- **首选**：直接拿 **WSL 的 Windows 宿主**当靶——管理员 PowerShell
  `Add-WindowsCapability OpenSSH.Server`，建**本地标准账号**（随机口令、只授登录），
  `sshd_config` 分别用 `ForceCommand C:\Windows\System32\cmd.exe` 与 `...powershell.exe`
  开两个端口（如 2200/2201），WSL 经宿主网关连入。**代价与风险要先讲**：这是往负责人的
  日常电脑上开 SSH 服务；用完是否卸载、防火墙放行范围（仅 WSL 段）由负责人定。
- **次选**：QEMU + Windows Eval ISO（需 `/dev/kvm` 可用，WSL 内嵌套虚拟化未必开；10–20G 磁盘）。
- **验证点**（清单已在进度手册 §6）：7 条信息收集脚本、上传（压缩/不压缩各一次，字节数比对）、
  下载回环、维持一组 deploy→verify→revoke，全部 **cmd 与 PS 两条会话各跑一遍**；
  失败路径（nologin/ForceCommand 变体）同样要指名原因。
- **做完后**：A2 的「PowerShell 脚本补齐」才算真闭环；F3 的 7 条 Windows 脚本从「无真机」出账。

### 批 E · 等外部条件的（不排工期，条件一到就做）
- **R8**：负责人撤销暴露 token（一分钟）；续托管改文件递送。
- **R7**：HBC 平台可用后跑回归（token 只走环境变量）。
- **RDP 的「不可判定」**、SNMP 边界、泛解析解析器差异：**维持现状**，它们是设计出来的诚实边界。

### 里程碑口径
- **1.6.2（靶场补齐版）**：批 A+C+D 完成即发（纯验证与测试性改动，对外行为不变）；
  批 B 完成后视缺口并入 1.6.2 或独立 1.6.3；R6 的结论必须出现在 1.6.2 的「验证」里
  （届时已有两周样本）。
