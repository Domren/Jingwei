## B. 弱口令检测（独立模块 · 深度利用二级栏 · 常见协议全套）

**命名（2026-11-04 定）**：对外一律叫**弱口令检测**——侧栏二级栏、页面标题、报告章节名、代码头部注释都用它；内部标识符保留 `credscan` / `cred_tasks` / `cred_results`（改代码名的收益不抵改动面）。

**定位（一句话，写进 `scanner/credscan.go` 头部注释）**：只负责**测出并记下这条事实**——
某资产的某协议存在某组可用凭据。它不编排别的模块，不自动触发任何动作，不自动复用凭据。

**「联动」= 数据可见，不是流程耦合**。这是本模块唯一要保证的接合方式：

| 谁读这条事实 | 读到什么 |
| :-- | :-- |
| 资产页 / 内网拓扑 | 该 `host:port` 有 service 行，并标注该协议存在弱口令 |
| 发现列表 | 一条 `weak-credential` finding，带 `protocol` + 原始协议字节（走 #81 定下的非 HTTP 证据通道） |
| 凭据库 | 多一条 `source=weakpass` 的凭据；**用不用由人决定**，模块不代劳 |
| LLM 规划 | 通过已有的资产 / 凭据查询工具读到「这条路可走」，从而自己决定下一步 |
| 报告 | 自动进弱口令章节 + 原始协议报文附录 |

**明确不做**（上一版误加、现已删除）：扫描任务勾选联动、扫描完成后自动建检测任务、
命中后自动开 SSH 会话、凭据跨主机自动撞库。

**协议范围：一次规划到位**。分档是**同一功能内的实现顺序**，不是「半年后的第二批」：

| 档 | 协议 | 为什么这么分 |
| :-- | :-- | :-- |
| 一档（Go 生态现成、字节可控） | SSH（`x/crypto/ssh` 已在 `go.mod`）、MySQL、PostgreSQL、Redis、MongoDB、Memcached、Elasticsearch、FTP、Telnet、VNC、Zookeeper、Socks5、SMTP / POP3 / IMAP（含 SSL 变体）、LDAP / LDAPS、SNMP、Web Basic Auth、WebDAV、Tomcat 管理控制台 | 认证握手有成熟库，能逐字节拿到请求与响应，满足证据要求 |
| 二档（需 NTLM / SOAP / 私有握手） | MSSQL、SMB 匿名与 IPC$、WinRM / WMI、Oracle Listener、RouterOS、CobaltStrike 面板默认凭据、Jenkins 匿名与弱口令、SVN | 要自己实现或半实现握手，工作量大但字节仍可控 |
| 三档（第一版**显式报不支持**） | RDP（NLA）、WebLogic / Jboss 控制台 | 版本差异大、握手不透明。宁可报「不支持」，也不要给出「测过了但结论不可信」的结果——那比没测更坏 |

**端口决策三级优先**（同样写进代码注释）
1. 输入显式带端口（`ip:port` / `[ipv6]:port` / `domain:port`）→ 只用该端口，不再猜；
2. 未带端口但端口探测 / 指纹已判定 `host:port` 属于某服务 → 按服务测；
3. 只给 IP / 域名且探测无结果 → 用协议默认端口表（22 / 3306 / 6379 / 21 / 445 / 1433 / 3389 / 5432 / 27017 …）。

硬约束：**默认端口表只用于「测哪个端口」，绝不用于「推断该端口是什么协议」**；协议判定只认 banner / 指纹，
否则 2222 上的 HTTP 会被当 SSH 打字典。

**数据模型**

| 表 | 关键列 |
| :-- | :-- |
| `cred_tasks` | `name`、`targets jsonb`（原始输入 + 解析后的 host/port）、`protocols`、`dict_profile`、`concurrency` / `rate_limit` / `budget_seconds`、`status` / `stage` / `progress` / `summary` / `log` / `error` |
| `cred_results` | `cred_task_id`、`host`、`port`、`protocol`、`username`、`password`、`outcome`（hit / deny / unreachable / **locked** / **不可判定** / **不支持**）、`banner`、`raw_request` / `raw_response`、`attempts`、`elapsed_ms`、`finding_id`、`credential_id` |

## 明确不做

多用户与角色、任务归属与交接、审批流、组织协作视图、Web 界面重写、白盒代码审计（除非变成「从拿到的源码/配置里提取凭据」这种服务于内网横向的形态）、商业验证码协议绕过（极验/易盾明确报不支持）。

若将来真出现多人需求：**一人一实例 + 数据导出**，而不是往平台里塞权限模型。

## 里程碑建议

- **1.4.2（小版本，低风险）**：分两步小版本发：**1.4.2 先发 A6 + A4**（当天量，纯配置与文档：`.env.example` 补变量、DEPLOY 补内网章节、发版口径写明「不留旧镜像、回退靠源码重建或 GHCR」）；**1.4.3 再发 A1 A2 A3 + A5**（真机隧道与非 POSIX 通道要重建 netns、逐条验，账期长，不跟文档类改动挤在一个版本里）。E2 G2 I3 跟 A1 那轮一起收。全是清账与可观测，不动接口。
- **1.5.0（能力版本）**：B1、B2、B3a、B3b、B5–B13、C1 C2 C5、D1 D2、E1、F3 F4、G1、H1–H3、I1 I2。
  主线是「弱口令检测进基线 + 复测与报告闭环 + 侦察面补齐」。
- **1.6.0（深度版本）**：B4（二档 NTLM/SOAP 协议）、C3、D3 D4 D5、E3 E4、F1 F2 F5 F6、G3 G4、I4。按四批顺序推进；空间测绘 C4 按负责人决定不做。
  主线是「域与横向深度 + 长跑可靠性 + 抗检测可解释」。

## 排期上的两条硬规则

1. **每个 B/C/D 组条目落地时同步加 `tools/e2e/` 项数**，并在 CHANGELOG「验证」小节写明在哪个靶机上验的——这是本项目区别于普通扫描器的地方，不能断。
2. **含安全修复一律走新小版本、不移动已发布标签**（1.4.1 已确立口径）；功能版本才动 minor。
